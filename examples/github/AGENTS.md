# GitHub CI PoC — Agent Runbook

Goal: deploy this example, connect one public GitHub repository, and prove a
push creates a successful Cloudflare Workflow run.

## Guardrails

- GitHub repositories must be public; this PoC has no GitHub API credential.
- Use a unique webhook secret.
- Restrict `sourceControl` to the target `{ owner, repo }`.
- Adapt pipeline commands to the target repository before enabling its webhook.
- Never commit `.dev.vars`, API tokens, R2 keys, or webhook secrets.
- Never create Access `Bypass` or `Everyone` policies. Managed Cloudflare
  accounts may delete them automatically.

## Target repository contract

Inspect the target before deployment. The example currently expects:

- `package-lock.json`
- `npm ci`
- scripts: `lint`, `test`, `typecheck`, `build`
- a Wrangler-deployable Worker for the final deploy step

If the target differs, edit `cloudflare.ci.ts`: package manager, cache inputs,
commands, and optional deploy step.

Set the repository restriction:

```ts
export const sourceControl = github({
  owner: '<github-owner>',
  repo: '<github-repository>',
});
```

## Required values

```text
GITHUB_WEBHOOK_SECRET             random value, e.g. `openssl rand -hex 32`
CLOUDFLARE_ACCOUNT_ID             account hosting CI, Workflow, Sandbox, and R2
CLOUDFLARE_DEPLOY_ACCOUNT_ID      account receiving the pipeline deployment
CLOUDFLARE_DEPLOY_API_TOKEN       API token for the deployment target
R2_ACCESS_KEY_ID                  R2 S3 credential for the CI host account
R2_SECRET_ACCESS_KEY              matching R2 S3 secret
```

The two account IDs may be identical. Create an R2 token with Object Read &
Write permission from the CI host account's R2 API Tokens page.

## Option A: Deploy to Cloudflare

Use the button in `README.md`. Human interaction is required for Cloudflare
login, account selection, and secret entry. After deployment, clone the
repository generated by Deploy to Cloudflare, apply the target repository and
pipeline edits above, and let Workers Builds redeploy it.

Record the resulting Worker hostname. The webhook endpoint is:

```text
https://<worker-host>/webhooks/github
```

## Option B: Local deployment

```sh
git clone --branch github git@github.com:cloudflare/ci.git
cd ci/examples/github
pnpm install --frozen-lockfile
cp .dev.vars.example .dev.vars
# Fill .dev.vars; do not commit it.
export CLOUDFLARE_ACCOUNT_ID='<ci-host-account-id>'
pnpm exec wrangler r2 bucket create cloudflare-ci-github-backups
pnpm deploy
pnpm exec wrangler secret bulk .dev.vars
```

If resource names already exist, choose unique Worker, Workflow, container, and
bucket names in `wrangler.jsonc`; keep `BACKUP_BUCKET_NAME` equal to the bucket
name.

## Cloudflare Access

First probe the endpoint without a GitHub signature:

```sh
curl -i -X POST https://<worker-host>/webhooks/github
```

Expected: `401`. A `302`, `403`, or `200` HTML page means Access intercepted the
request.

If a broader Access application protects the hostname, create a more-specific
application for `<worker-host>/webhooks/github`. Use a Service Auth
(`non_identity`) policy restricted to GitHub's current hook CIDRs. Fetch them
from `https://api.github.com/meta` (`.hooks`). Do not use Bypass or Everyone.
The new `cf` CLI supports:

```sh
cf zero-trust access applications create --body '<json>'
```

Application body shape:

```json
{
  "type": "self_hosted",
  "name": "GitHub CI webhook",
  "domain": "<worker-host>/webhooks/github",
  "session_duration": "24h",
  "policies": [
    {
      "name": "GitHub webhook source networks",
      "decision": "non_identity",
      "include": [{ "ip": { "ip": "<one GitHub hooks CIDR>" } }],
      "exclude": [],
      "require": []
    }
  ]
}
```

Include every current `.hooks` CIDR. Local traffic should remain `403`; signed
GitHub traffic should reach the Worker.

## Configure GitHub

Repository **Settings → Webhooks → Add webhook**:

```text
Payload URL:  https://<worker-host>/webhooks/github
Content type: application/json
Secret:       GITHUB_WEBHOOK_SECRET
Events:       push only
```

With authenticated `gh`, an agent may create the hook via `gh api`; avoid
printing the secret.

## Verify

Push a commit. The GitHub delivery must return `202` (not `200`). Then:

```sh
pnpm exec wrangler workflows instances list cloudflare-ci-github --reverse
pnpm exec wrangler workflows instances describe cloudflare-ci-github <instance-id>
```

Success means install, lint, test, typecheck, build, and optional deploy steps
all complete. Diagnose `200` plus no Workflow instance as an Access login page,
not webhook success.
